## 2. 📱 手機同步 App：導入流程、費用、架構

### 2-1. 為什麼要做
- Strava 爬蟲違反 Strava 服務條款；Strava 官方 API（2024 年後）也禁止把使用者資料顯示給其他人（排行榜玩法不被允許）。
- 改由玩家手機的 **Apple 健康 / Google Health Connect** 讀取，支援小米、Apple Watch、Pixel Watch、Garmin、Samsung 等所有會同步到手機健康資料庫的手錶，還能取得步數、睡眠、靜止心率等新數據。

### 2-2. 費用
| 項目 | 費用 | 備註 |
|---|---|---|
| Apple Developer Program | **US$99／年** | 必付，iPhone 版 TestFlight 發佈 |
| Google Play Console | **US$25（一次）** | 建議付（自動更新）；也可直接傳 APK 免費 |
| Supabase / Vercel | US$0 | 免費方案足夠 20 人 |
| iOS 編譯 (Codemagic) | US$0 | 沒有 Mac 用雲端編譯，免費額度約 500 分鐘／月 |
| **合計** | **第一年約 US$124，之後每年 US$99** | |

### 2-3. 架構
```
手錶 App → 手機健康資料庫 (Apple 健康 / Health Connect)
        → 鋼鐵英雄同步器 App (Flutter，一套程式碼雙平台)
        → Supabase Edge Function (register-device / ingest-health，裝置專屬金鑰驗證)
        → Supabase (activities + daily_health) → 網站計分
```
- App 原始碼：Google Drive「BugFixed12/13」資料夾內的 `iron-heroes-mobile-app-*.zip`，或本機 `iron-heroes-mobile/`。說明在其 `README_zh-TW.md`。
- App 收集的數據（v1.1）：運動紀錄（類型／時間／時長／平均與最高心率／熱量／距離）、每日步數、活動熱量、**中高強度活動分鐘**（心率 ≥ 最大心率 64%）、**睡眠時長＋入睡／起床時間**、**靜止心率**（由睡眠中最低 30 分鐘平均心率推算，各品牌一致）。HRV／血氧僅顯示不計分。不收集體重、體脂、爬升、VO₂max。
- App 會跳過 Strava 寫回手機的紀錄；跨來源重複由網站「疑似重複判定」處理。

### 2-4. 啟用步驟（全部可用 Windows 完成，詳見 `docs/MOBILE_SYNC_SETUP.md`）
1. Supabase → SQL Editor 執行 `scripts/supabase_migration_mobile_v1.sql`（只新增欄位與資料表，不動舊資料）。
2. 安裝 Node.js → `npx supabase login` → `link` → `secrets set GM_PASSWORD=<GM 密碼>` → 部署 `register-device`、`ingest-health`、`admin-mobile`。
3. 申請 Apple / Google 開發者帳號 → 依 App 的 README 用 Codemagic 編譯 → TestFlight 公開連結 / Google Play 內部測試。
4. GM 後台「📱 手機同步 App 管理中心」→ 勾選啟用、填下載連結 → 產生邀請碼 → 把邀請連結貼到群組。
5. 與 Strava 並行 1–2 週，看「⚖️ 來源對帳」全員 ✅ 一致 → GitHub Actions 停用 `strava_crawler`。

### 2-5. 注意事項
- TestFlight 每個版本 90 天到期，每季重新上傳一次（玩家按「更新」即可）。
- iPhone 背景同步時間由 iOS 決定、鎖屏時讀不到健康資料 → 偶爾請玩家打開 App。
- Apple Watch / 部分小米手環在非運動時段心率取樣較稀疏，活動分鐘可能偏低；請玩家開啟「連續心率監測」。
- App 目前只通過程式檢查與 46 個單元測試，**第一次 Codemagic 編譯可能需要小修正**。

### 4-2. 📱 手機同步資料片（必須先開啟手機同步 App）
所有參數都可在 GM 後台「選擇資料片 → 下方參數面板」調整；前台會用目前參數顯示完整公式與設計原因。**每日得分 × 當日限時加成倍率；缺資料不倒扣。**

**🗺️ 資料片八：萬步遠征**
- 每日里程 = min(步數, 每日上限 25,000) ÷ 1,300 步/km ＋ 有效運動分鐘 × 0.05 km ＋ 騎車距離 × 0.3 ＋ 游泳距離 × 4
- 原因：步數讓日常移動有貢獻；重訓沒有距離所以用運動分鐘換算；跑步距離已含在步數中不重複計。
- 勝利：全服累計里程抵達終點（預設環台 1,200 km，城市里程碑可自訂）；公會依里程排名。

**🌙 資料片九：夢境守護者**
- 每天最高 100 分：睡眠分 = min(睡眠, 7h)/7h × 60；規律分 = max(0, 1 − |入睡時間 − 個人前 14 晚中位數| / 60 分) × 20；攻擊分 = min(有效運動分鐘, 60)/60 × 20
- 原因：鼓勵睡飽＋作息規律（跟自己的習慣比，夜貓子規律也能滿分）＋白天運動；不用睡眠分期（品牌差異大）。
- 勝利：全服傷害打完夢魘血量（= 英雄數 × 賽季天數 × 60）；公會依人均傷害排名。

**🕯️ 資料片十一：不滅之火**
- 每人每日三道火：① 活動分鐘 ≥ 30 或完成一次有效運動 ② 步數 ≥ 8,000 ③ 睡眠 ≥ 7h
- 公會：所有「有資料」成員都 ≥ 2 道火 → 聖火熱度 +1（× 加成）；有成員 0 道火 → −1；沒資料的成員不列入判定。
- 勝利：賽季結束時聖火等級最高的公會（同級比總火種）。

**🧘 資料片十三：鐵人修行院（跟自己比）**
- 每日修為 = min(TRIMP,150)/150 × 40 ＋ min(睡眠,7h)/7h × 30 ＋ min(活動分鐘,30)/30 × 10
- 走火入魔：急性負荷(7 天 TRIMP) ÷ 慢性負荷(28 天 TRIMP ÷ 4) > 1.5 且近 3 晚平均睡眠 < 6h → 當日 × 0.5（慢性負荷需 ≥ 每週 100 TRIMP 才判定，新手不會被誤判）
- 靜心加成 = max(0, 基準靜止心率 − 近 7 天中位數) × 150（基準 = 賽季前 7 天中位數）
- 勝利：依總修為晉級（初學者 → 行者 1200 → 武僧 2800 → 羅漢 4800 → 宗師 7200，可自訂）；公會依人均修為排名。

### 4-3. 開/關手機同步的保護機制
- 手機同步**關閉**時：新資料片在 GM 選單中為停用狀態；網站不讀取任何手機資料、不發出額外請求。
- 進行中的是手機資料片時，GM **無法關閉**手機同步（會提示先切回經典資料片）。
- 若資料異常（模式是手機資料片但同步被關），前台顯示提示而非錯誤，所有經典資料片照常運作。

## 6. 其他重要事項
- **徽章起算日**：上線後到 GM 後台設定（例如本季 2026/10/19）；留空 = 採計全部歷史。
- **安全性（尚未處理）**：Supabase 公開金鑰有寫入權限、GM 密碼只在前端檢查。目前玩家都是熟人可接受；若擴大到陌生人或商業化，需改為後端驗證與 RLS 收緊。
- **Strava 爬蟲監控**：每次更新程式後到 GitHub Actions 確認綠燈；紅燈不影響既有資料，只是暫時沒有新資料。
- **周邊**：Drive「鋼鐵英雄紀元 徽章周邊 4K 印刷檔」有 6 枚徽章 4096×4096 抱枕印刷檔（有標題版／純圖版）。
- **QA 方式**：所有更新都以 headless Chrome 自動化測試（手機 390px／電腦 1440px，點擊所有按鈕、GM 寫入→重新整理→前台回讀），寫入一律攔截到模擬資料庫，不碰正式資料。
